# Security

Until a public release is qualified, development previews are unsupported for sensitive workflows. Use synthetic evidence for public issues. Do not post private HARs, logs, screenshots, credentials or report bundles publicly.

Once the repository is published, report a vulnerability privately through GitHub vulnerability reporting. Its exact private-report link will be added after that setting is enabled. No private reporting channel is claimed as active before then.

Files are processed locally and originals are not automatically archived. Automatic credential patterns are incomplete. Review every cleaned value and screenshot before sharing. Limits and worker cancellation reduce accidental resource use but do not make the application a hostile-file security sandbox.
