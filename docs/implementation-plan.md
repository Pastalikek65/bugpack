# BugPack implementation contract

User-approved product: inspect HAR, UTF-8 logs and PNG/JPEG screenshots locally, redact sensitive values, review outputs, and export only regenerated clean files in a ZIP with a Markdown bug report and explicit processing summary. No account, backend upload, paid API or original attachments. Apache-2.0; English product/docs and Turkish quickstart. Static self-hosted distribution on Windows/Linux x64; later CLI shares the same core. No guarantee of finding all personal information.

## Architecture and boundaries

TypeScript/React/Vite static app with pure TypeScript redaction and packaging in a dedicated Web Worker. No remote fonts, analytics, embedded external links, fetch of file contents, or service worker. CSP restricts connection destinations. Only generated neutral filenames go in ZIP. Text is escaped by React, never HTML injected. All originals remain in-memory inputs; never mutate source bytes. No originals in archive. Explicit review checkbox gates export, invalidates on any input/output/policy/mask change. Raw preview must be visibly distinguished from sanitized preview. Text edits regenerate archive from the edited cleaned values. Images are decoded under dimension/pixel limits, rendered to a fresh canvas, covered by fully opaque integer pixel masks, regenerated as PNG with only required chunks. Always include a mask count and review instruction, do not claim detection of screenshot secrets.

MVP: validate bounded HAR1.2 entries, project supported fields onto a fresh allowlist, remove authentication/cookies, sanitize URL query credentials, discard ALL request/response bodies and unknown extensions with explicit omission counts. Known textual HTTP fields are preserved only under an allowlist; filename/URL/path leftovers must be inspected. Logs support UTF-8 only, known authorization/key-value tokens/JWT patterns; manual entire text editing. ZIP generated from only sanitized bytes with neutral entry names plus report and summary; no path input API. PNG/JPEG upload, dimensions/pixel validation before browser decode, permanent opaque masks, regenerated PNG. 16MiB per input, 64MiB aggregate, 50 files, 5000 HAR entries, depth40/node200000 JSON budget, 16M image pixels/8192 dimension, 128MiB regenerated bundle/output limit, 60-second worker operation deadline and explicit cancellation. These are input/output limits, not an OS memory sandbox.

v1: versioned import/export local redaction policies; bounded literal custom rules rather than user regex; structured JSON and URL-encoded form bodies opt-in under a policy, recursive sensitive-key redaction and original-body discard on unsupported/invalid/binary content. Batch processing states show successes, failed and omitted files; failed inputs never silently become archive originals. Node24 CLI uses same engine for HAR/log; image output/masking must use an explicit supported image processor and actual metadata/pixel checks, or be explicitly scoped to browser when deciding CLI support. Unknown policy versions fail with a clear error.

## Visual design

An evidence review workbench: a restrained steel-blue/pale blue-gray palette (#f6f8fc background, #ffffff paper, #182b49 text, #365c92 primary, #dbe4ef rules, #b24b31 omissions). Local Segoe UI/Arial typography; code textarea monospace for actual file content only. Left evidence list, central original/clean comparison or image canvas with opaque rectangles, right export/report panel. Visible state labels and omission counts serve the review. Responsive stacked panels with visible keyboard focus; keyboard numeric mask coordinates as well as mouse drag. No decorative gradients, marketing hero, speculative privacy seal, or filler cards.
