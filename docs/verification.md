# Verification

Use a release's `verification.json` and `SHA256SUMS` to identify the exact qualified source, archives and evidence. Documentation-only commits may summarize a completed release gate; they do not change or requalify an archive. Qualification requires fresh Windows/Linux CI, actual source and extracted-package browser/policy/CLI flows, portable startup and format compatibility, dependency/license checks, raw performance records and independent review. A green build alone is insufficient. Test and review evidence is limited to the reported hosts and synthetic inputs; it does not establish universal privacy or an OS resource sandbox.

The MVP [0.1.0 release](https://github.com/Pastalikek65/bugpack/releases/tag/v0.1.0) was qualified at `de47154576f9e260fa6de286d785bbca56c1f77d`, CI `37897925690`: each platform passed 33 tests in five files and twelve real browser steps in source/package, including opaque/all-unmasked pixels, seeded-secret ZIP checks and the whole 33-file package. The exact Windows CI ZIP also passed on Windows 11.

The 0.2.0 beta source `20c6cc524dc0cd4153c0ae718a606507c6ee9aad`, CI `37912575939`, passed 73 tests in nine files per platform, actual browser 12/policy 9/CLI 11 steps in source and package, full 39-file package comparison and a zero-vulnerability full dependency audit. The same Windows CI ZIP passed the three suites on Windows 11 under an extraction path containing spaces. Actual Windows start.cmd startup, packaged index/security headers and owned-process cleanup were also checked. Four source/package benchmark records are described in [performance](performance.md).

## Stable 1.0.0 release

The [1.0.0 release](https://github.com/Pastalikek65/bugpack/releases/tag/v1.0.0) was built from `97805ce3d17384f91e0b6afced4587bfd3c55bf7`; its [CI run 37921280761](https://github.com/Pastalikek65/bugpack/actions/runs/37921280761) passed on Windows and Ubuntu 24.04 x64. Each platform passed 74 tests across nine files. In source and extracted-package modes, browser acceptance passed 12 steps, policy acceptance 9 and CLI acceptance 11. Portable startup passed 6 checks and format compatibility passed 11 calls per platform. Four synthetic benchmark records cover the source and package modes on both platforms. CI acceptance compared all 42 package files with the archive before and after the flows. The release's `verification.json` binds the exact source, archives and raw records and records the independent-review disposition and limitations.

The same server-digest-verified Windows CI ZIP also passed all six flows on Windows 11 x64. This is supplemental Windows 11 evidence; Linux results come from the Ubuntu 24.04 CI host. The Windows 11 proof record has SHA-256 `5744d81e1e5d766d532f16b10f1bc2e291a1c0f50e4b2e7b0068510b3191deae`. These results cover the stated hosts and synthetic inputs, not a universal privacy guarantee or an OS process sandbox.

The 1.0.0 archives were built before final qualification, so their bundled `docs/verification.md` retains the candidate-era wording present at build time. This later source documentation records the completed release evidence; it is not part of the 1.0.0 archives and does not change, rebuild or retag them. Use the release's `verification.json` and `SHA256SUMS` for the archive identities.

Versioned compatibility covers policy schema 1 and summary schemas 1/2. The app does not store its workspace or import output ZIPs. Old reviewed HAR/log text can be processed again, but an omitted body and its old summary count history cannot be restored from that text.

## Retained early MVP development records

The following records describe earlier snapshots, including failures that were fixed before the public MVP. They are preserved as history, not current beta test totals.

Initial local core review reproduced: semicolon cookie values escaping line cleanup; lost first-pass HAR omission counts in the bundle summary; repeated redaction markers inflating counts; quoted JSON credentials and AWS/OAuth/Azure/GCS signed-URL values escaping fixed patterns. Each received a failed regression before a fix. Image-header regressions cover repeated JPEG frame headers, EXIF bounds, PNG IHDR checksum/settings and animation rejection. Raw private reproductions remain retained; committed tests require the corrected behavior.

The first browser harness run failed because its title expectation omitted the app subtitle. That was a harness expectation error, not a product defect. The actual source-suite ZIP download now passes after its timing fix; exact-source cross-platform package qualification is still pending. Failures remain visible rather than marking the workflow successful.

The initial pinned dependency audit has zero reported vulnerabilities. This statement belongs to that snapshot; exact releases require a fresh full audit. Input/output limits do not establish an OS process-memory bound.

Local pre-freeze Windows 11 source flow passed 25 tests across four files, typecheck and production build. The strengthened actual browser suite passed 11 steps, including native ZIP downloads, all declared secret-seed presence/absence checks, first-pass omission retention, full-mask opaque pixels, equality of every unmasked RGBA pixel against the original, JPEG-to-PNG metadata removal, failed-input export blocking, invalid UTF-8/size rejection, CSP-blocked reachable canary and unchanged input/application bytes. This is source evidence, not Linux or release-package qualification. The earlier ZIP-ready/no-download defect was reproduced in a real 30-second download timeout; moving the link click to the committed React effect fixed the same acceptance without a fallback click or weakened assertion.

First exact-source CI 37895748209 at fba76eb failed the Linux preflight: Git stored sample.har with LF after its first staging pass, while its original fixture and manifest use CRLF. Direct Git-blob/worktree comparison reproduced the exact mismatch; re-adding that file with the existing no-text-conversion attribute preserved the original bytes and expected hash. No fixture regeneration or expectation change was used. The harness now retains an initial identity failure before browser launch as a failure record. A new exact-source CI run is required; the earlier failed run does not qualify a release.

The current source harness passes 12 steps, adding an explicit cancellation case to the earlier 11-step run: DevTools pauses a real spawned processing worker before its script starts, the user-facing Cancel action terminates that target, and neither the active nor queued input becomes ready. The workspace can remove both failed rows and cannot export them. This controls scheduling; it does not claim natural-workload cancellation timing or a 60-second deadline test. The evidence records `chromiumSandboxRequested`, not a measured OS sandbox state. Packaged acceptance now validates and reads the shipped manifest and examples rather than relying on repository copies.

The bounded static-package inspector passes eight archive regressions (33 tests in five files overall). Packaged browser acceptance now compares every extracted file and directory to the ZIP or TAR archive before startup and after all twelve steps. The retained local pre-freeze Windows archive passes this strengthened check; it remains a development snapshot, not an exact-source release candidate.
