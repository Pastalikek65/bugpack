# Supported inputs and limits

The MVP supports HAR 1.2 JSON, UTF-8 `.log`/`.txt`, still PNG and supported JPEG screenshots. The product is a static browser app; packaged use requires Node.js 24 for the bundled localhost server and a current Chromium browser. Windows and Linux x64 are qualification targets. A graphical browser is needed; CLI cleanup is scheduled for v1. Files do not get uploaded to a backend. Server scripts listen only on 127.0.0.1 and reject POST; self-hosting the static web directory requires a trustworthy origin and security headers.

HAR cleanup creates a fresh projection of supported fields. Authentication/cookies, unapproved headers, unknown extensions, comments and request/response body contents are dropped. The supported response status and timing fields remain useful for debugging, but full HAR information is deliberately not retained. Supported URLs keep their hostname/path and noncredential query fields; inspect these for private values. The summary counts omitted data rather than treating it as reviewed preserved content.

Text cleanup uses fixed credential patterns, including authorization/cookie lines, quoted or unquoted credential assignments, JWT-like values and common signed-URL keys. It cannot classify arbitrary private strings, names or personal values. Edit the clean copy manually. A clean HAR edit must remain valid supported HAR; export sanitizes it again. The Markdown report also receives fixed credential cleanup.

Images are validated before decoding, drawn to a fresh canvas, covered by integer-coordinate opaque masks, and encoded as PNG. PNG ancillary metadata and JPEG source metadata are not retained. Animated PNG is unsupported. Image processing checks dimensions before browser decoding and after orientation; these checks do not make the browser an OS memory sandbox. Removing a mask affects only the local review workspace; the already exported PNG contains no reversible mask layer.

Limits: 16 MiB per original file and per cleaned/edited text, 64 MiB aggregate original inputs, 50 files, 5,000 HAR entries, 200,000 JSON nodes and depth 40. Images are at most 8,192 pixels on a side and 16,000,000 decoded pixels. Regenerated image bytes and total uncompressed bundle contents are bounded by 128 MiB; the completed ZIP has the same 128 MiB cap. Worker operations have a 60-second deadline and can be cancelled. These are rejection limits, not throughput guarantees or a process-memory ceiling. Malformed or unsupported input fails explicitly and is never archived as its original.

Processing counts include app-reported first-pass redaction/omission facts and any export-pass changes. They describe operations and omissions, not a proof that no secret remains. Source filenames and absolute paths are not included automatically. A user can still write private information into a report or miss a screenshot mask; review all outputs before sharing.
